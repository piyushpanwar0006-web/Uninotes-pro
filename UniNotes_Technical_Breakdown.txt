🎓 UniNotes: Technical System Breakdown & Reverse-Engineering

As a senior architect and code auditor, I have conducted a deep-dive analysis of the UniNotes codebase. Below is the complete technical documentation, architectural mapping, and security audit of the platform.

---

1. Core Tech Stack Identification

UniNotes is built using a modern, high-performance Serverless JAMstack architecture.

- Frontend Framework: Next.js 14 (App Router)
- Styling: Tailwind CSS
- Backend-as-a-Service: Supabase
- Database: PostgreSQL (Supabase)
- Authentication: Supabase Auth (GoTrue)
- File Storage: Supabase Storage (S3-compatible)
- Infrastructure: Netlify

---

2. Project Architecture & Folder Structure

UniNotes follows a Component-Based Architecture within the Next.js App Router paradigm.

Folder Structure Breakdown:
- src/app: The Routing Layer. Contains both Page components (UI) and Route Handlers (API).
- src/components: The Atomic UI Layer. Reusable components like Navbar, Footer, and PaperCard.
- src/lib/supabase: The Connectivity Layer. Houses the client-side, server-side, and administrative Supabase configurations.
- src/services: The Business Logic Layer. Decouples complex logic from the UI components.
- supabase/migrations: The Schema Layer. SQL scripts defining the database structure, triggers, and indices.

Data Flow Pattern:
1. Request: User interacts with a PaperCard to view or delete.
2. Logic: Frontend calls a Next.js Route Handler (e.g., DELETE /api/papers/[id]).
3. Auth: middleware.ts intercepts the request to verify/refresh the Supabase session via cookies.
4. Service: The Route Handler uses the Service Role client (Admin) to perform authorized operations.
5. Response: JSON payload returned; React state updates for a reactive UI update.

---

3. Security Implementation Audit

- Authentication: Uses JWT (JSON Web Tokens) stored in secure, HTTP-only cookies.
- Authorization (RBAC): User vs Admin roles enforced via server-side checks in API routes.
- Database Security (RLS): Row Level Security is enabled on PostgreSQL.
- Storage Security: Private buckets with Signed URLs for PDF access.
- Input Validation: API routes use Zod to sanitize and validate incoming requests.

---

4. Core Feature Engineering

PDF Upload Flow:
1. Storage Phase: The file is uploaded to Supabase Storage using a UUID filename.
2. Metadata Phase: Database record is created in the papers table linking the storage_path.

The Deletion Logic:
1. API removes binary from Storage.
2. API deletes record from PostgreSQL.

---

5. Database Schema (PostgreSQL)

- users: Profile data + role (user/admin).
- subjects: Academic catalog (branch, semester, code).
- papers: Metadata for PDFs (title, storage_path, uploaded_by).
- bookmarks: Junction table for user-saved resources.

---

6. Critical Bug Analysis
Issue: "When I delete a PDF, it shows success but after refresh it comes back."

Root Cause Identification:
- Caching (Most Likely): Next.js/Netlify aggressive caching. GET /api/papers might be cached at Browser or CDN level.
- Fix: Use 'Cache-Control: no-store, max-age=0' headers and ensure fetchCache = 'force-no-store' is set in the route.

---

7. Scalability & Improvements

- Performance: Move to Full-Text Search (FTS) using PostgreSQL tsvector.
- Security: Implement Rate Limiting on upload endpoints.
- Scaling: Use Redis (Upstash) for caching frequently accessed subject listings.

---

Final Verdict:
UniNotes is a well-engineered platform. The bug is a common "Stale Cache" symptom in JAMstack apps and can be resolved with stricter cache-control headers.
